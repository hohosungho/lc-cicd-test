[사용자 지시 원문 — 이 단계가 하는 일은 항목 2, 3, 4 중 코드 부분(appspec, 훅 스크립트, 골든 AMI 설치 스크립트, 앱, GitHub Actions)이다]
사용자가 방향을 바꿨다. 이전 계획의 AWS 실행 단계(apply-*, tests-*, teardown 실행)는 모두 폐기하고 아래로 대체한다.

1. AWS 리소스는 에이전트가 만들지 않는다. 사용자가 콘솔에서 직접 만든다. 따라서 에이전트는 어떤 AWS 변경 명령(create/apply/put/update/delete)도 실행하지 않는다. 읽기 전용 조회도 필요 없으면 하지 않는다. 대신 콘솔 기준 '예상 구성' 가이드를 문서로 제공한다: 리소스별로 콘솔 메뉴 경로, 입력할 값(이름은 접두사 lc, 리전 ap-northeast-2, 계정 866477832211, 태그 Project=lcamtest/Owner=sungho/Ephemeral=true, ALB 인바운드 허용 IP <MY_IP>/32), 만드는 순서, 각 단계 확인 방법. 순서는 문서 §6 ASG 도입 순서(단독 Web 1대 → 골든 AMI → ASG min0/desired0 수동 모드 → desired 1 → 2 → 자동복구 해제 → 정책)를 따른다. IaC 템플릿은 만들지 않는다.
2. 앱 코드는 대충대충. 최소 Laravel(또는 그에 준하는 최소 PHP 앱)로, 화면(/)에 버전, 태그, 릴리스 SHA, instance-id(IMDSv2), AZ, 시간을 크게 보여주고 SHA 기반 배경색으로 배포마다 눈에 띄게 바뀌게 한다. /up(헬스, 고장 스위치로 500 가능), /version(JSON)만 있으면 된다. DB/Redis/세션/큐 로직 없음. Queue/Scheduler 역할은 더미 heartbeat만. 앱 품질·테스트에 공들이지 않는다. 앱 코드 리뷰 반복(루프)은 불필요하다.
3. GitHub Actions 는 알작딱 최소본: OIDC 역할 사용(장기 키 금지), 빌드 → zip → S3 deploy 버킷 업로드 → aws deploy create-deployment → wait. 정적 자산 sync는 --delete 금지. 사용자가 콘솔로 만든 리소스의 이름/ARN은 repo variables 로 넣도록 문서화.
4. 초점은 CodeDeploy + ASG 에서 배포가 어떻게 진행되는지. 따라서 다음에 가장 공을 들인다: appspec.yml과 훅 스크립트(stop/before_install/after_install/start/validate, 문서 §5-1 설계 그대로: 스테이징 _incoming → releases/$DEPLOYMENT_ID → current 심볼릭 링크, DEPLOYMENT_GROUP_NAME 분기, 고장 스위치로 각 훅 실패 재현), 골든 AMI 만드는 절차(콘솔 + 인스턴스 안에서 돌릴 설치 스크립트) 등.
산출물 중 이 단계 담당: app/ (최소 앱), appspec.yml, scripts/ (훅 스크립트), ami/ (골든 AMI 설치 스크립트), .github/workflows/deploy.yml. 검증: 스크립트는 bash -n 과 (있으면) shellcheck, appspec/워크플로 YAML 유효성을 통과해야 한다.
